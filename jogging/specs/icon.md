# Piece: icon

App icon, generated by a re-runnable script. Source: `docs/todo.md`, first item.

## What it delivers

The launcher icon, the themed (monochrome) icon for Android 13+ and the notification icon
are redrawn as geometric vector art produced by one script, `scripts/icon.mjs`. Changing
the icon means editing the script and re-running it; a test fails CI if the committed
resources and the script disagree. The 15 per-density WebP files go.

Goals it leans on: 7 (simple over clever, minimal dependencies, testing pyramid) and 2
(the notification icon is part of the daily reminder, so it must still render in the
status bar). Goals 1 and 4 are untouched: no data, no scheduling. No decision in
`GOALS.md` covers icons. Per the release decision, the piece ends with a `minor` bump.

### Tool choice

`docs/todo.md` suggests Pillow "or another tool". The script is **Node with no
dependencies**, emitting Android `VectorDrawable` XML and an SVG, not Pillow rasters:

- `scripts/` is already Node, tested by `node --test 'scripts/*.test.mjs'`, which CI runs.
  Pillow would add Python to the toolchain and to CI (goal 7).
- One vector per icon replaces five densities each, and stays sharp at every size.
- Generated text can be compared byte for byte with the committed files, which is what
  makes "re-runnable" enforceable.
- The SVG is what the web app's manifest and Home Screen icon will be made from.

## Design

### Art

A side-on tortoise walking right, flat and geometric, in the app's palette
(`ui/theme/Color.kt`):

| Part | Colour (full-colour icon) |
|---|---|
| Background (adaptive icon background) | Evergreen `#2F5D50` |
| Shell: a dome cut into plates (scutes) | ShellAmberDark `#E7BE8A` |
| Head, neck, four stubby legs, tail | Parchment `#F7F4EE` |
| Eye | a hole in the head |
| Ground: a row of three short rounded blanks under the feet, the review screen's blank motif | Parchment at 60% alpha |

The **one rule** that keeps all three outputs consistent: every visible gap (between
shell plates, between shell and body, the eye) is an *absence of paint*, never paint in the
background colour. Then the same shape list renders as the colour icon (each part its
colour), the monochrome icon (every part one opaque colour, the system tints it) and the
notification icon (every part white), and the gaps survive in all three. The eye is the
head path with an inner circle and `android:fillType="evenOdd"`; nothing else may
overlap it.

The exact proportions are the build session's to tune by eye, inside these limits:

- **Adaptive icon canvas** is 108×108 with the art inside the 66-diameter safe circle
  centred on (54, 54): masks (circle, squircle, teardrop) crop everything outside it.
  The art should fill most of that circle's width; the old art was centred and too small
  (bounding box about 50×28 of 108).
- **Notification icon** is a 24×24 viewport with the art inside the central 20×20 (2
  padding each side), white on transparent. At that size the ground blanks are dropped and
  the shell gaps must stay at least 1 unit wide at 24 scale, or they fill in at 24dp mdpi.
- No gradients, no shadows, no text.

### Script: `scripts/icon.mjs`

Pure functions plus a `main` that writes files, the same shape as `bump-version.mjs` /
`version.mjs` but in one file, since the logic is small:

- **Primitives** that return SVG path data and a list of outline points: `circle`,
  `ellipse`, `roundRect`, `polygon`, `dome` (upper half-ellipse), with a `holes` option
  for the eye. Numbers are written with at most two decimal places, so output is stable.
- **`parts`**: the tortoise as a list of `{ name, role, path, points }`, where `role` is
  `shell`, `body` or `ground`. Coordinates are in the 108 canvas.
- **Renderers**, each pure and returning a string:
  - `launcherForeground()` → `VectorDrawable` 108dp, colour by role.
  - `launcherMonochrome()` → `VectorDrawable` 108dp, every part `#FFFFFFFF`.
  - `notification()` → `VectorDrawable` 24dp, a `<group>` with `scaleX/Y` and
    `translateX/Y` mapping the art's bounds (ground excluded) into the 2..22 box, white.
  - `backgroundColour()` → the `values/ic_launcher_background.xml` resource.
  - `previewSvg()` → a 108×108 SVG with the Evergreen background and the colour art,
    for viewing in a browser and for the web app.
- **`outputs()`** returns `[{ path, text }]` for every generated file. `main` writes them
  with LF endings (git's `core.autocrlf` handles Windows checkouts).
- Usage: `node scripts/icon.mjs`, no arguments.

No Room, backup or settings change, so no migration. `isShrinkResources` keeps the
drawables because the adaptive icon and `R.drawable.ic_notification` reference them.

Lint may warn `VectorPath` (long path data); warnings don't fail CI. Fix any lint
*error* in the generator, not by suppressing it.

### Tests: `scripts/icon.test.mjs`

Run by the existing `node --test 'scripts/*.test.mjs'`, so CI picks them up unchanged.

- **Drift:** for every entry in `outputs()`, the committed file (CRLF normalised to LF,
  via `readRepoFile` from `scripts/repo-files.mjs`) equals `text`. Failure message names
  the file and says to run `node scripts/icon.mjs`.
- **Safe zone:** every outline point of every launcher part is within radius 33 of
  (54, 54).
- **Fills the zone:** the art's bounding box is at least 52 wide, so it can't shrink back
  to the old size.
- **Notification bounds:** after the group transform, every non-ground point lies within
  [2, 22] on both axes.
- **Monochrome and notification are single-colour:** their XML contains no `fillColor`
  other than white.

## Build steps

Each step follows `CLAUDE.md`'s Workflow and `PROTOCOL.md`. "Passing" means every
command exits 0.

### build-1: generator, art and tests (Sonnet, high)

Write `scripts/icon.mjs` and `scripts/icon.test.mjs` as above, run the script, delete the
15 WebP files and their directories, and iterate on the art until it looks right.

Effort is high because the art is tuned by eye over several render-and-look rounds.

To look at the art, render the preview to PNG with headless Edge and open the PNG with
the Read tool (render at a few sizes; 48 px is roughly a launcher icon, 24 px a
notification):

```bash
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless --disable-gpu \
  --screenshot="$TEMP/icon-432.png" --window-size=432,432 "file:///D:/lab/TortoiseSpelling/docs/icon.svg"
```

For the notification art, temporarily write a white-on-dark SVG of `notification()`'s
shapes to `$TEMP` the same way; don't commit it.

Acceptance:

```bash
node scripts/icon.mjs && git status --short     # second run: no further changes
node --test 'scripts/*.test.mjs'                # all pass, including icon.test.mjs
./gradlew assembleDebug testDebugUnitTest lintDebug
```

- `git ls-files 'app/src/main/res/drawable-*'` prints nothing.
- Re-running `node scripts/icon.mjs` leaves `git status` clean.
- Temporarily changing a colour in `icon.mjs` without re-running makes the drift test
  fail (then revert).
- The rendered preview reads as a tortoise at 48 px, and the notification silhouette
  reads as a tortoise at 24 px.

Commit the generator, tests and generated files. No CHANGELOG line yet (build-2 adds it
with the docs).

### build-2: on the device, release build and docs (Sonnet, medium)

Check the icon where users see it, then write the docs.

1. Start the emulator if needed, install the debug APK, and screenshot
   (`adb exec-out screencap -p > $TEMP/x.png`, then Read it):
   - the launcher icon on the home screen or app drawer;
   - the themed icon: Settings → Wallpaper & style → Themed icons on (Android 13+),
     back to the home screen;
   - the notification: in the app, Settings → "Send a test notification", then pull
     down the shade (`adb shell cmd statusbar expand-notifications`).
   Fix anything wrong in `icon.mjs` and re-run it.
2. Build a release APK signed with the debug keystore (`CLAUDE.md`, "Release build"),
   install it, and confirm the launcher icon and notification icon still appear (R8 and
   resource shrinking).
3. Update `CHANGELOG.md`, `CLAUDE.md` and `docs/todo.md` as in **Docs**.
4. Run the e2e suite (`cd e2e && npm run e2e`), since the step touches the app.
   Stop the emulator.

Acceptance:

```bash
node --test 'scripts/*.test.mjs'
./gradlew testDebugUnitTest lintDebug assembleRelease
cd e2e && npm run check-steps -- --all && npm run typecheck && npm run e2e
```

All pass, and the three screenshots show the new tortoise: full colour in the launcher,
tinted in themed mode, and a white silhouette in the status bar and shade.

### review (Sonnet, medium)

Review the piece against this spec and `GOALS.md`: art inside the safe zone in a
circular mask, gaps visible in monochrome and notification, no hand-edited generated
file, docs updated, no war-story comments in `icon.mjs`. Re-run the build-2 acceptance
commands. Then, because the app changes for users, run
`node scripts/bump-version.mjs minor`, check the `CHANGELOG.md` section it moved, and
commit and push.

## What later pieces rely on

No piece depends on this one. `web-ui` (manifest and Home Screen install) should take its
icons from `docs/icon.svg`, or add renderers to `scripts/icon.mjs` for whatever it needs
(for example a maskable SVG, or a PNG rasterised at build time for the iOS
`apple-touch-icon`), so both apps keep one source of truth.
